MODULE 2

Mathematical Analysis of Recursive Algorithms

Learning outcomes: set up a recurrence with an initial condition; solve it by backward substitution and verify it; draw a recursion tree; explain why naive Fibonacci is slow; compare recursion with iteration.

The five-step plan

The five steps are the same as in Module 1 (size, basic operation, cases, count, solve), but step 4 gives a recurrence relation: an equation for the count \(M(n)\) through the count for smaller arguments, together with an initial condition from the stopping case.

Backward substitution

  1. Write the recurrence and the initial condition.
  2. Substitute the recurrence into itself 2–3 times, keeping the structure visible (write \(2^2M(n-2)+2+1\), not \(4M(n-2)+3\)).
  3. Spot the pattern after \(i\) substitutions.
  4. Choose \(i\) so the argument reaches the initial condition.
  5. Simplify with the formulas of Module 1.
  6. Verify by plugging the answer into the recurrence and the initial condition (or by induction).

Worked examples

Example 1. Factorial (from the lecture)

Input size: \(n\). Basic operation: multiplication. Cases: one case. Recurrence: \(F(n)\) calls \(F(n-1)\) and then multiplies once. Initial condition: F(0) returns 1 without multiplying.

\[M(n)=M(n-1)+1\ (n>0),\qquad M(0)=0.\]

Backward substitution:

\[M(n)=M(n-1)+1=M(n-2)+2=M(n-3)+3=\dots=M(n-i)+i.\]

Take \(i=n\): \(M(n)=M(0)+n\).

\[M(n)=n\in\Theta(n).\]

Verify: \(M(0)=0\) ✓ and \(M(n-1)+1=(n-1)+1=n\) ✓. Why it matters: the loop version also needs \(n\) multiplications, but recursion uses \(n\) stack frames, so memory is \(\Theta(n)\).

Example 2. Tower of Hanoi (from the lecture)

Input size: the number of disks \(n\). Basic operation: moving one disk. Cases: one case. Idea: move \(n-1\) disks aside, move the largest disk, move the \(n-1\) disks back on top.

\[M(n)=2M(n-1)+1\ (n>1),\qquad M(1)=1.\]

Backward substitution (after \(i\) steps):

\[M(n)=2^{i}M(n-i)+2^{i-1}+\dots+2+1=2^{i}M(n-i)+2^{i}-1.\]

Take \(i=n-1\):

\[M(n)=2^{n-1}\cdot1+2^{n-1}-1=2^n-1\in\Theta(2^n).\]

Numbers: 10 disks need 1023 moves, 20 disks need 1 048 575, 64 disks need about \(1.8\cdot10^{19}\). The tree of calls has levels with \(1,2,4\) calls for \(n=3\), in total \(7=2^3-1\), which confirms the formula.

Why it matters: the exponential growth is a property of the problem, not of this algorithm (no algorithm can do better). Recursion can hide this cost behind short code.

Example 3. Counting binary digits, \(n=2^k\) (from the lecture)

Input size: \(n\). Basic operation: the addition. Cases: one case. Recurrence: \(n\) has one more binary digit than \(\lfloor n/2\rfloor\).

\[A(n)=A(\lfloor n/2\rfloor)+1\ (n>1),\qquad A(1)=0.\]

The floor makes substitution messy, so first take \(n=2^k\):

\[A(2^k)=A(2^{k-1})+1=A(2^{k-2})+2=\dots=A(2^{k-i})+i=A(2^0)+k=k.\]

Since \(k=\log_2n\):

\[A(n)=\log_2n\in\Theta(\log n)\quad(\text{exactly }\lfloor\log_2n\rfloor\text{ for all }n).\]

Check: \(n=8=1000_2\) has 4 digits and needs 3 additions. Why it matters: halving problems (binary search, bit counting) are logarithmic, so \(n=10^9\) needs only about 30 steps.

Original example 1. Recursive maximum (Student 3)

Code: Max(A,n): if \(n=1\) return A[0]; otherwise compare Max(A,n-1) with A[n-1] and return the larger. Input size: \(n\). Basic operation: the comparison. Cases: one case.

\[C(n)=C(n-1)+1\ (n>1),\qquad C(1)=0\ \Rightarrow\ C(n)=n-1\in\Theta(n).\]

Why it matters: it has the same comparisons as the loop in Module 1, but uses \(\Theta(n)\) stack, so a loop is safer for huge arrays.

Original example 2. Fast exponentiation, \(n=2^k\) (Student 4)

Code: Pow(a,n): if \(n=1\) return \(a\); otherwise \(p\leftarrow\)Pow(a,n/2) and return \(p\cdot p\). Input size: \(n\). Basic operation: multiplication. Cases: one case.

\[M(n)=M(n/2)+1,\quad M(1)=0\ \Rightarrow\ M(2^k)=M(2^{k-1})+1=\dots=k=\log_2n.\]

Check: \(a^{8}\) needs 3 multiplications, not 7. Why it matters: computing \(a^{1024}\) takes 10 multiplications instead of 1023; the idea is used in hash functions and in computing Fibonacci numbers by matrix powers.

Warning: naive Fibonacci

Code: F(n): if \(n\le1\) return \(n\); else return F(n-1)+F(n-2). Basic operation: the addition.

\[A(n)=A(n-1)+A(n-2)+1,\qquad A(0)=A(1)=0.\]

Put \(B(n)=A(n)+1\). Then \(B(n)=B(n-1)+B(n-2)\) is the Fibonacci recurrence, so

\[A(n)=F(n+1)-1\in\Theta(\varphi^n),\qquad\varphi=\tfrac{1+\sqrt5}2\approx1.618.\]

Why it is slow: the recursion tree computes \(F(n-2)\) twice, \(F(n-3)\) three times, and so on, while only \(n+1\) different values exist. Fixes: memoization (store each \(F(k)\) in a table the first time) or a loop keeping the last two values: \(n-1\) additions, \(\Theta(n)\). General lesson: a correct recursive definition with overlapping subproblems can be hopelessly slow.

Recursion vs. iteration

Recursion mirrors definitions and gives short code (trees, divide and conquer), but the call stack uses memory. Report stack depth as space complexity. Example: a recursive directory scan can overflow the stack on a very deep folder tree.

AlgorithmTimeStack depth
Factorial\(\Theta(n)\)\(\Theta(n)\)
Binary digits\(\Theta(\log n)\)\(\Theta(\log n)\)
Tower of Hanoi\(\Theta(2^n)\)\(\Theta(n)\)
Naive Fibonacci\(\Theta(\varphi^n)\)\(\Theta(n)\)

Tail recursion (the recursive call is the last action) can be turned into a loop mechanically, and some compilers do it automatically.
