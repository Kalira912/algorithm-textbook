Introduction: the essential ideas

Input size and basic operation

Input size describes how much data an algorithm receives. For an array, it is usually the number of elements, \(n\). The basic operation is the operation whose count best represents the algorithm's running time, such as a comparison between two array elements.

Asymptotic notation

\(O(g(n))\) — asymptotic upper bound
\(\Omega(g(n))\) — asymptotic lower bound
\(\Theta(g(n))\) — matching upper and lower bound

For example, if an algorithm performs \(3n^2 + 2n + 7\) basic operations, its growth is \(\Theta(n^2)\). For large \(n\), the quadratic term dominates; constants and lower-order terms do not change the order.

NotationMeaningExample
\(O(n)\)At most linear growth up to a constant factorScanning an array once
\(\Omega(n)\)At least linear growth up to a constant factorReading all \(n\) input values
\(\Theta(n)\)Both upper and lower linear boundsComputing the sum of \(n\) values

Cases

Best case: the most favourable input of a given size. Worst case: the least favourable input. Average case: expected cost under an explicitly stated probability model.

Glossary

TermDefinition
AlgorithmA finite sequence of well-defined steps for solving a problem.
Input sizeA parameter describing the amount of input data.
Basic operationThe selected operation whose frequency is counted.
Order of growthHow the operation count increases as input size increases.
RecurrenceAn equation defining a function in terms of smaller inputs.
Base caseA small input for which a recursive algorithm returns directly.
Recursion treeA diagram showing recursive calls and their work.
MemoizationStoring computed results to avoid repeated work.
Stack depthThe number of active function calls stored on the call stack.
Empirical verificationTesting a predicted operation count by running an instrumented program.
